# 要件定義（タスク管理アプリセカンドリリース２月１６日）

## 背景

現代人は毎日、タスクをこなしています。

しかし、それぞれのタスクをどのように優先順位をつけて進めていくかわからなかったり、適切にアウトプットができずにいます。また、それぞれのタスクがどれくらい密度が高いのかわからずに進めていくために、タスクの負荷も考慮したタスク管理ができないという問題があります。

## 課題

- それぞれのタスクの優先順位が適切に管理されていない
- それぞれのタスクに対して、しっかりアウトプットができていない
- それぞれのタスクの密度（負荷）を考慮した上で、タスクを管理できていない

## 目的

- タスクを適切に管理（優先順位、アウトプット、負荷）する仕組みを作る
- あとからタスク（アウトプット、負荷）を振り返りができるように、検索や比較や再利用ができるようにする

## 機能要件（MVP版）

### タスク機能

- タスクを作成できる（日付、タイトル、それぞれの子タスク（優先度、密度、タスク名、継続時間、カテゴリー選択）、1日の振り返り）
  - タスク作成時は、まとめてタスクを作成できるようにする。これまではいずれかの時間（15分、30分、45分、60分）で子タスクを作成できるようにしていたが、90分〜360分とまとめて作成できるようにする。ただし、90分以降は30分の子タスクに分割される。（例：90分→30分、30分、30分）
  - 初期カテゴリーがない状態でもカテゴリーを選択できるようにする。（例：インプット系、思考系、文章系、作業系、コミュニケーション系）
  - 追加された子タスクについてはコピーできる。
- 自分が作ったタスクを編集、削除できる（物理削除）
  - 編集は作成と同様
- 自分が作ったタスクはマイページで一覧表示できる
- 自分が作ったタスクはマイページの詳細で確認できる
- タスクを検索できる（タスクのタイトルとそれぞれの子タスクの部分一致）
- 自分が作った子タスクで、子タスク終了後にアウトプットができる
- 自分が作った子タスクで、子タスクの優先度、密度、カテゴリー、継続時間をそれぞれ別に編集できる
- タスクのデータ画面で、月別のタスクのデータを確認できる。具体的なデータは以下に記載
  1. 月別のタスクの総合データ（累計作業時間⚫️時間⚫️分、予定作業時間⚫️時間⚫️分、累計タスク数⚫️数、予定タスク数⚫️数、完了率⚫️．⚫️%）
  2. 月別のタスクの負荷別データ（高負荷、中負荷、低負荷、⚫️時間⚫️分、⚫️．⚫️%、円グラフで表記）
  3. 月別のタスクのカテゴリー別データ（上位4つのカテゴリー別の時間、⚫️時間⚫️分、棒グラフで表記）
  4. 月別のタスクの日別のデータ（1日ごとのタスクの時間と負荷別の時間を棒グラフで表記）

### カテゴリー機能

- カテゴリーの情報（カテゴリー名）を追加できる。
- カテゴリーを一覧で確認しつつカテゴリーの編集、削除ができる。

## 将来の拡張予定

- それぞれ子タスクのアウトプットについてテンプレートからアウトプットの形式を選択できる（未定）
- 他人のタスクのアウトプットも見れる状態にする（優先度高）
- タスクの進め方について、優先度によってレコメンドされる（※現時点でイメージできず）
- その日の状況（気温、湿度、気圧、天気）もタスクと一緒に記録する。（※外部APIと連携して実装予定）（優先度高）
- 中長期のタスクについても設定できる。（例：長期は⚫️⚫️と期間（⚫️⚫️年⚫️月）、中期は⚫️⚫️と⚫️日分）
- AIで自動にカテゴリーやタスクの負荷を割り当てる機能作成予定（優先度超高い）
- 何かしらのメール機能とCSVインポートエクスポート機能

## 非機能要件（MVP）

- 認証：Googleログイン/ログアウト/初回登録（OAuth2）
- データベース：Postgres、正規化されたテーブル構造
- 検索：（タスクのタイトルとそれぞれの子タスクの部分一致）
- UI：PCブラウザ対応（スマホ最適化なし）
- パフォーマンス：軽量シングルユーザー規模を想定
- デプロイ：Cloud Run + Cloud Build（自動デプロイ）
- CI/CD：GitHub Actions
- 監視：Cloud Loggingのみ（最低限）

## 他ツールとの差別化

- それぞれのタスクについてアウトプットができ、あとで振り返りができる
- それぞれのタスクについて負荷も考慮にいれて、管理ができる
